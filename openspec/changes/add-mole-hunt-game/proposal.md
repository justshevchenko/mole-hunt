# Proposal

## Why

Потрібен сайт із грою «Полювання на кротів»: за 20 секунд гравець влучає в кротів, що випадково з'являються на полі 5×5, а результати всіх гравців потрапляють у спільну таблицю лідерів. Проєкт порожній — це перша зміна, яка створює гру повністю: від ігрового поля до збереження результатів у базі даних.

## What Changes

- Статичний сайт (HTML/CSS/JS), розміщений на GitHub Pages, з адаптивним полем 5×5, що працює і мишею, і дотиком.
- Три екрани: стартовий (короткі правила і кнопка «Розпочати») → гра → результат (бали, кубок, турнірна таблиця, «Грати ще» одразу веде на екран гри).
- Візуальна тема «Весняна галявина»: мультяшні кроти, що виринають з нірок, і кубок «Кріт у кубку» в золоті, сріблі чи бронзі.
- Ігровий цикл на 20 секунд: випадкова поява 1–3 кротів одночасно, таймер, бали (+1 за влучання, −1 за клік по порожній клітинці, мінімум 0). Частота появи залежить від рівня: на легкому й середньому новий кріт кожні 0,6–1 с, на складному в 1,5 раза частіше, на епічному — утричі.
- Чотири швидкості зникання кротів (легка 4 с, середня 3 с, складна 2 с, епічна 1 с) і п'ять режимів: чотири фіксовані та «Авто». Режим перемикається на екрані гри будь-коли; перша гра стартує на «Середньому», наступні — у режимі, на якому закінчилась попередня. Кожен кріт живе за швидкістю, чинною в момент його появи.
- Авторежим: старт на середній (або на поточній, якщо увімкнено посеред гри), 3 влучання поспіль → рівень +1, клік повз → рівень −1, на межах рівень не змінюється.
- Анонімна ідентифікація гравця без реєстрації: ID у localStorage, ім'я вводиться один раз після першої гри і не змінюється; без імені — «Гість N» зі спільного лічильника.
- Екран результату з кубком (золотий/срібний/бронзовий) поруч із балами і підписом «Ура! Золото!», «Вітаю зі сріблом!» чи «Бронзовий призер!» за правилами 1–3 місця.
- Спільна таблиця лідерів за найкращим результатом: топ-10, підсвічений рядок поточного гравця, «…» і його рядок, якщо він нижче 10-го місця, режим рекордної гри як інформація.
- Бекенд на Supabase (Postgres): таблиці гравців і результатів, SQL-функції для реєстрації гравця, запису результату з перевіркою меж і отримання таблиці лідерів. Браузер не має прямого доступу на запис до таблиць.

## Capabilities

### New Capabilities
- `game-flow`: стартовий екран із правилами, три екрани гри і переходи між ними.
- `gameplay`: ігрове поле 5×5, поява і зникання кротів, таймер на 20 секунд, підрахунок балів.
- `difficulty`: швидкості зникання кротів, п'ять режимів, правила авторежиму та перемикання режиму під час гри.
- `player-identity`: анонімний ID гравця, одноразове введення імені, автоматичні імена «Гість N».
- `leaderboard`: збереження результатів, ранжування за найкращим результатом, вигляд таблиці лідерів.
- `game-results`: екран результату після гри, правила видачі кубків і їх показ поруч із балами.

## Impact

- Новий фронтенд у репозиторії `mole-hunt` (статичні файли без збирача або з мінімальним збирачем) і GitHub Actions / налаштування GitHub Pages для публікації.
- Новий проєкт Supabase: SQL-міграції (таблиці, послідовність для гостей, RLS, функції `register_player`, `submit_score`, `get_leaderboard`), зберігаються в репозиторії.
- Залежність: `@supabase/supabase-js` (через CDN або npm).
- Публічний (anon) ключ Supabase потрапляє у фронтенд — це очікувано; захист даних забезпечують RLS і SQL-функції. Сервісний ключ у репозиторій не потрапляє.
- Обмеження безкоштовного тарифу Supabase: проєкт ставиться на паузу після ~7 днів без активності, і його треба відновити вручну.
